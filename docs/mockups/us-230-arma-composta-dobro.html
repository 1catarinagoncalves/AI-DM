O que muda na implementação

  1. Guerreiro/Paladino: o slot original (2 alternativas, AMBAS genéricas) vira 2 EquipmentChoiceSlot em resolveEquipmentSlots, não 1 — equipmentChoices[i] ganha 1 índice a mais a partir daí. Na UI, o radio escolhe o MODO ("+ escudo" ou "em dobro") e os dois modos compartilham o MESMO <select> de arma (a lista de armas marciais é idêntica nos dois) — só o texto do resultado muda (", Escudo" vs. " (2)"). Fica pra implementação decidir se isso é 1 EquipmentChoiceSlot com um campo de modo extra, ou os 2 slots continuam existindo por baixo e a UI só reaproveita o valor de um select pro outro.
  2. Patrulheiro: só 1 das 2 alternativas do slot é genérica ("Espada Curta (2)" continua nomeada) — flattenWeaponOptions expande só a genérica, mesmo mecanismo de sempre, sem dividir slot.
  3. qty: 2 é sempre da MESMA arma escolhida (confirmado pela mantenedora) — nunca duas armas diferentes, nunca 2 itens separados de qty: 1.
  4. "Escudo" no padrão composto é string literal fixa, nunca resolvida contra config.weapons (não existe catálogo de armadura/escudo no projeto) — aparece igual em toda <option> do select de "arma + escudo".
